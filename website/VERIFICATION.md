Une vérification partielle du dashboard a été réalisée dans Chrome isolé : portfolio desktop, corbeille et paramètres d’identité desktop/mobile, contacts et fiche prospect desktop/mobile, timeline desktop/mobile statistiques mobile et partage desktop/mobile. Les captures et mesures se trouvent dans `verification/screenshots/`. Le viewport mobile est réellement émulé à 390 × 844 px ; largeur du document et largeur défilable égales à 390 px. Le parcours mini-site décrit ci-dessous ajoute une vérification Chrome desktop/mobile ; les gestes sur téléphone, vrais scans et l’ensemble des autres vues restent à vérifier. Une URL HTTPS de backend IA a été demandée pour vérifier une génération réelle. Le serveur actuel est local, lié à 127.0.0.1 : un téléphone ne peut pas scanner son URL localhost pour atteindre ce serveur.

Commandes : `npm ci`, `npm start`, `npm test` depuis website.

`frontend.test.mjs` exécute le JavaScript du site dans jsdom avec des réponses API simulées. Il prouve le fonctionnement de l’édition de brouillon, du choix de photo, de la réouverture d’une variante et du CTA intérêt. Il ne vérifie ni le rendu CSS ni la 3D ni les gestes réels sur téléphone. Quarante et un tests passent via `npm test` (API serveur et interactions DOM), dernière exécution le 5 octobre 2026. Les quatre tests `WebsiteSyncTests` vérifient avec un transport HTTPS simulé la création app → web, l’import web → app, les offres/mesures, la conservation des éditions et l’absence de doublons ; ils ne remplacent pas un essai sur un serveur HTTPS réel.

La synchronisation tourne dans l’app au premier plan. Les changements hors ligne sont repris au retour de la connexion. Elle ne transfère pas encore toutes les archives techniques de scan (frames, checkpoints) et synchronise la mise à la corbeille et la restauration des biens ; les suppressions individuelles de fiches commerciales restent à raccorder. Les conflits sur les biens sont résolus dans l’interface de partage ; les conflits commerciaux sont signalés dans l’état global de synchronisation.

La corbeille est vérifiée par tests API et DOM : retrait, restauration, persistance du marqueur sur disque, blocage d’un ancien retry de création, maintien du slug et des offres, désactivation du mini-site, refus d’un retrait après modification concurrente. Le test iOS de l’espace partagé est étendu aux retraits/restaurations des deux côtés ; les vues de corbeille desktop/mobile ont été capturées ; un essai sur serveur HTTPS réel reste nécessaire.

Commande reproductible : `npm run verify:visual`. Elle lance un serveur et un profil Chrome temporaires, avec un jeu de données indépendant du store courant ; contrôle la largeur du viewport et du document, puis capture les vues. `CHROME_BINARY` permet de choisir le binaire Chrome. Aucun profil de navigation utilisateur ni serveur de données courant n’est utilisé. Les captures de cette commande ne prouvent pas la connexion réelle iPhone/HTTPS.

L’identité commune est vérifiée par API et DOM : fusion de champs distincts, refus d’une modification simultanée, choix de la valeur locale/serveur sans perdre les autres champs du formulaire, validation des URLs/couleur/emails, propagation aux biens liés et maintien des présentations personnalisées. Le test iOS couvre l’import web, le retour d’une modification locale, l’effacement d’un champ, les deux choix de résolution et la conservation de saisies faites pendant une requête. Captures et mesures ajoutées pour `agent-settings-desktop` et `agent-settings-mobile`. Les parcours iOS visuels et la connexion à un serveur HTTPS réel restent à vérifier.

La synchronisation des caractéristiques d’un bien conserve les saisies faites pendant une requête. Le test `propertyEditsDuringSendSurviveAndKeepConflictBaselines` vérifie un titre remplacé pendant l’envoi, l’effacement d’un prix, une nouvelle ville, leur envoi au cycle suivant et le refus d’écraser une description modifiée en parallèle sur le web. Le transport reste simulé ; les modifications de photos/scans pendant leurs téléchargements nécessitent une vérification séparée.

  -destination 'platform=iOS Simulator,name=iPhone 17' \

L’éditeur importe désormais GLB et USDZ (50 Mo maximum). `glb-data.mjs` vérifie le conteneur GLB 2 : signature, version/longueur, première section JSON, alignement et limites des sections, version d’asset et taille du buffer intégré. Les ressources externes sont refusées pour les imports afin de conserver un fichier autonome.
